
# 砚迹（YanTrace）- 版本管理


## 一、版本号规范

采用 **语义化版本 2.0.0**：`主版本号.次版本号.修订号`

| 类型 | 规则 | 示例 |
|------|------|------|
| **主版本号** | 可以发布的正式版本迭代 | `v2.0.0` |
| **次版本号** | 向下兼容的新功能 | `v0.2.0` |
| **修订号** | 向下兼容的问题修复 | `v0.2.1` |


## 二、提交信息规范

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(practice): 新增浮动输入框` |
| `fix` | Bug 修复 | `fix(stat): 修复退格计数重复问题` |
| `docs` | 文档更新 | `docs: 更新设计文档` |
| `style` | 样式调整（不影响逻辑） | `style: 优化统计栏布局` |
| `refactor` | 重构（不改变功能） | `refactor(practice): 拆分 practice.js` |
| `chore` | 构建/工具/依赖 | `chore: 删除无用代码` |


## 三、分支管理

### 3.1 分支策略

采用 **Git Flow 简化版**：
```
master (稳定版)
│
└── develop (开发集成)
│
├── feature/* (新功能)
└── fix/* (Bug 修复) 
```

### 3.2 分支说明

| 分支 | 用途 | 说明 |
|------|------|------|
| `master` | 稳定版本 | 只接受从 `develop` 或 `release/*` 合并 |
| `develop` | 开发集成 | 所有功能分支的集成分支 |
| `feature/*` | 新功能开发 | 从 `develop` 拉出，完成后合并回 `develop` |
| `fix/*` | Bug 修复 | 从 `develop` 或 `master` 拉出 |

## 五、版本更新规则

| 更新类型 | 版本号变化 | 触发场景 |
|----------|-----------|----------|
| 次版本 | v0.1.0 -> v0.2.0 | 模块完成、新功能、重大改动 |
