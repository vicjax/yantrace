# 砚迹（YanTrace）- 版本管理


## 一、版本号规范

采用 **语义化版本 2.0.0**：`主版本号.次版本号.修订号`

| 类型 | 规则 | 示例 |
|------|------|------|
| **主版本号** | 不兼容的 API 修改、重大架构重构 | `v2.0.0` |
| **次版本号** | 向下兼容的新功能 | `v1.1.0` |
| **修订号** | 向下兼容的问题修复 | `v1.0.1` |


## 二、提交信息规范

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(practice): 新增浮动输入框` |
| `fix` | Bug 修复 | `fix(stat): 修复退格计数重复问题` |
| `docs` | 文档更新 | `docs: 更新设计文档` |
| `style` | 样式调整（不影响逻辑） | `style: 优化统计栏布局` |
| `refactor` | 重构（不改变功能） | `refactor(practice): 拆分 practice.js` |
| `chore` | 构建/工具/依赖 | `chore: 删除无用代码` |


## 三、分支管理

### 3.1 分支策略
```
采用 **Git Flow 简化版**，适合单人/小型项目：
master (稳定版，可发布)
│
└── develop (开发集成分支)
│
├── feature/* (新功能)
├── fix/* (Bug 修复)
└── release/* (发布准备)
```

### 3.2 分支说明

| 分支 | 用途 | 说明 |
|------|------|------|
| `master` | 稳定版本 | 只接受从 `develop` 或 `release/*` 合并，可随时发布 |
| `develop` | 开发集成 | 所有功能分支的集成分支 |
| `feature/*` | 新功能开发 | 从 `develop` 拉出，完成后合并回 `develop` |
| `fix/*` | Bug 修复 | 从 `develop` 或 `master` 拉出 |
| `release/*` | 发布准备 | 从 `develop` 拉出，准备发布到 `master` |

### 3.3 分支生命周期
```
v1.1.0 (已发布)
│
└── develop (创建)
│
├── feature/english-practice ──┐
│ (v1.2.0 开发) │
│ ▼
├── feature/input-module ──→ develop ──→ master (v1.2.0 发布)
│ (v1.3.0 开发) │
│ │
└── feature/cloud-sync ────────┘
(v2.0.0 未来)
```

### 3.4 常用操作

```bash
# 1. 从 develop 拉出功能分支
git checkout develop
git pull
git checkout -b feature/xxx

# 2. 开发完成后合并到 develop
git checkout develop
git pull
git merge feature/xxx
git branch -d feature/xxx

# 3. 发布版本（合并到 master 并打标签）
git checkout master
git merge develop
git tag -a v1.x.x -m "Release v1.x.x"
git push origin master --tags

# 4. 紧急修复（从 master 拉出）
git checkout master
git checkout -b fix/xxx
# 修复后合并回 master 和 develop
```
